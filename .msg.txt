docs: rewrite both READMEs around four questions

Replaces the previous structure with four sections that answer, in order: what
it is, what it does, what it offers, and how to use it. No account of how the
implementation got here.

The old README led with design inspiration and an evaluation table, which told a
reader where the ideas came from before saying what the plugin does. It also
described four capabilities in one table while the plugin now ships governance,
forgetting, and Dream alongside storage and consolidation.

Content changes worth noting:

- The six Settings tabs are documented. The previous version listed four; the
  forgetting and Dream panels were missing entirely.
- The forgetting lifecycle and the no-deletion guarantee are stated explicitly,
  because they are the properties a user needs before trusting the feature.
- Dream's two risk classes are explained: metadata actions can be undone by
  another metadata action, content changes cannot.
- The data layout now includes dream/ and governance/, which existed on disk but
  not in the documentation.
- Local-first is qualified: the authoritative data is local, the model calls are
  not.

Both languages carry the same 262 lines and the same section order, so a reader
can follow one against the other.
