fix(dream): keep Dream worker sessions out of the Session catalog

A Dream run appeared in the Session list as "dream-mw4ggocx — consolidated",
and the consolidation catalog offered it back as a conversation worth reviewing.
The run is internal; it was never a conversation.

The catalog excludes internal sessions by id pattern, and that pattern only knew
the consolidation worker prefix. Dream now creates its session as
`session-memory-dream-<runId>` and the same check recognises it.

This also explains the noise around the last two attempts: the worker session was
eligible for consolidation while the run itself was still pending, so the panel
showed unrelated consolidation activity for a Dream click.
