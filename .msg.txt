fix(client): show that a Dream run is in progress

Clicking Run produced no visible change for up to three minutes. The request was
working: the model proposed a set-priority that the new no-op check rejects, and
it then spends a correction round deciding what to do instead. The button was
disabled during that time but kept its idle label, so a live run and a dead
button looked identical.

The label now switches to "Running... this can take a few minutes" while busy.
That is the only signal the panel can give before the request settles, and
without it the honest reading of the screen is that the click did nothing.
